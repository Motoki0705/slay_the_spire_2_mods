# キャラの動作 — 動画生成AIの方針

ユーザー指定: 動画生成AIを使用。候補は **MiniMax H3 / Seedance 2.5**。モデルは未決定、動画生成は未実行。キャラデザインのレビュー後に進む。

追加要件（原文）:

> 動画生成AIの使用箇所も洗い出してください。選択画面のちょっとした動きや攻撃モーション等あると思います。これらの「動き」がある場所も特定してください。

選択画面のほか、戦闘、休憩所、商人、キャラ固有能力等の動作を、インストール済みゲームのシーン・リソース・APIと照合する。動画AIで作る候補と、ゲーム状態に応じて動作させる必要がある要素を分け、存在を確認した箇所だけを実装済みのゲーム機能として記録する。

## 動作の調査で記録する項目

- 発生する画面・状況、対象キャラ、動作名。
- シーン・アセット・コードの具体的な場所と調査対象バージョン。
- トリガー、ループの有無、割り込みや復帰条件。
- キャラ本体、装備、相棒、投射物、背景、UIのどこが動くか。
- 動画を直接再生するか、動画を素材としてフレーム等へ変換するか、ゲーム側の描画を維持するか。
- 生成素材に必要な構図・長さ・背景・開始終了姿勢と、未確認事項。

本書の下記演出は制作方針であり、ゲーム内のAPIや全動作が確認済みという意味ではない。

## 公式に案内される能力

| 候補 | 公式情報から確認した能力 | この制作で確かめる点 |
| --- | --- | --- |
| MiniMax H3 | 画像・動画等を参照する生成、最大15秒・2K出力 | 仮面や非人間の顔、細い骨、オーブを保った短い動作 |
| Seedance 2.5 | 最大30秒、複数の画像・動画を使った参照生成、時刻を指定した編集 | オスティーとの掛け合い、装備の一貫性、動作の修正しやすさ |

## 制作の流れ

1. 公式設定を反映したコンセプトをユーザーがレビューする。
2. 修正を反映して、キャラごとに正式な全身絵と必要な参照を作る。
3. 採用サービスの利用経路・設定を確認してから、同じキャラと動作条件の短い動画を試作する。
4. 本人らしさ、線と色、手足・仮面・骨・機械の形、装備と相棒の連続性を確認する。
5. ループ用の開始・終了姿勢を調整し、ゲームで使える再生形式・負荷・表示範囲を検証する。

候補の選定軸は、本作の絵柄とキャラの保持、動作の読みやすさ、ループの作りやすさ。画素数や尺だけでは決めない。

## 共通の演出指定

- 固定カメラ、全身が収まる構図。１つの短い仕草を中心にする。
- 背景とポーズの開始・終了を揃えることを目標にし、生成後に継ぎ目を検査する。
- 顔・衣装・種族・装備はレビュー済み画像から変えない。
- 視線誘導は仕草、色、固有能力で行う。身体を見せつけるポーズやカメラ移動は使わない。
- レビュー済みの人型女性デザインを基準にする。動画の途中で顔・髪・身体構造が原作の姿へ戻る、装備が別の物へ変わる等の意図しない変化を防ぐ。原作からの擬人化そのものは禁止しない。
- 操作ボタンと説明文はゲームUIとして表示する。生成動画に文字やUIを描き込まない。

透過動画の出力可否・対応API・ゲームへの具体的な組み込み形式は未確認。接続確認と試作の結果から決める。

## 原作の動作と再利用の検討

[動作調査](../../research/motion/inventory.md)で、キャラ本体はSpineとゲーム側の制御で動いていることを確認した。選択動画以外をすべて動画へ置換すると決定したわけではない。攻撃、死亡、相棒、剣、オーブ等はイベントやゲーム状態との連動を持つ。

既存骨格とモーションの再利用、新しい人型女性デザインへの再スキニング、新リグ、AI動画・連番との併用を、[実装方式](../../research/implementation/options.md)と[骨格再利用調査](../../research/implementation/rig-reuse.md)で比較する。どの方式でも、人型女性への翻案を弱めることを前提にしない。

[動画素材仕様と費用](../../research/costs/video-generation.md)は、元アニメの尺、生成する尺、必要な表示解像度、生成モデルの出力解像度と課金単位を分けて算定する。最短生成尺や再試行にかかる費用も含め、動画を作らず元のモーションを使う箇所を区別する。原作の全アニメの秒数を足すだけで生成費用とはしない。
